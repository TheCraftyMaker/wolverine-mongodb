# WolverineFx 6.65.1 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move Wolverine.MongoDB from WolverineFx 6.38.0 to 6.65.1, the latest stable 6.x release, with every
inherited compliance fact green and the two contract gaps that 6.65.1 exposes closed.

**Architecture:** One foundation PR does the parts that must change together: the package pins, the submodule, the
xunit.v3 4.x test host on Microsoft.Testing.Platform (MTP), the Bobcat leadership specs, the CI commands and the one
compile error. That PR also records which inherited facts fail. Each behaviour fix is its own PR, stacked on the
foundation branch and limited to its own diff. One docs PR collects the CHANGELOG, README, CLAUDE.md and FOLLOWUPS
changes, so that ten branches do not edit the same text.

**Tech Stack:** .NET 9/10, MongoDB.Driver 3.14.1, WolverineFx 6.65.1 (`external/wolverine` at `V6.65.1`), xunit.v3
4.0.2 on Microsoft.Testing.Platform 2.x, Bobcat 1.0.0, Shouldly, Testcontainers.MongoDb replica set.

**Spec:** the impact analysis of 2026-11-27 (summarised in "Verified facts") and the 6.38 upgrade plan
`docs/superpowers/plans/2026-09-15-wolverine-6.38-upgrade.md`, whose structure this plan follows.

## Review Focus

- **The deduplication claim must be released exactly once.** A failed attempt in a transactional handler must
  release the claim once, after the MongoDB rollback, so the retry runs and a parallel duplicate is still refused.
  Owned by Task 4.
- **Two nodes recover the same inbox page at the same time.** Each envelope must be queued by exactly one node,
  including when the two passes read the page in opposite orders. Owned by Task 3.
- **A handled-check on an envelope that is still running.** `IsHandledAsync` must say `false` for an `Incoming`,
  `Scheduled` or dead-lettered row and `true` only for a `Handled` row, by the same identity rule as `ExistsAsync`.
  Owned by Task 2.
- **A host that still sets `EnableMessageDeduplication = true`.** The property is obsolete but still works: it maps
  to `MessageDeduplicationMode.CompareByHash`. The MongoDB store must treat every mode except `None` as enabled.
  Owned by Task 1.
- **A local `dotnet test` on the demo with the .NET 10 SDK.** The repo-root `global.json` puts `dotnet test` in MTP
  mode, and the demo still runs xUnit 2 on VSTest. The demo must keep running from the command line. Owned by Task 1.

## Verified facts (2026-11-27, compared at tags V6.38.0 and V6.65.1)

- **Compile break, the only one:** `DurabilitySettings.EnableMessageDeduplication` is `[Obsolete]` (GH-4757). Its
  getter is `MessageDeduplicationMode != MessageDeduplicationMode.None`. Uses: `Internals/MongoDbMessageStore.cs:93`
  (code), `:89` and `Internals/MongoDbDeduplicationStore.cs:21` (doc comments), `logical_message_deduplication.cs:67`
  (test). `MessageDeduplicationMode` is `None`, `CompareByString`, `CompareByHash`. The two compare modes exist for
  RDBMS collations, and MongoDB compares `_id` strings byte by byte, so both map to the existing store.
- **No binary break.** Every interface member added between the two tags has a default implementation. The reflection
  targets the library reads (`SagaDescriptorBuilder.Build`, `WolverineOptions.HandlerGraph`, `HandlerGraph.Container`,
  `ClaimDeduplicationIdFrame._deduplicationId` / `._ancillaryStoreMarker` / `.Variable`) still exist. The demo CI run
  on WolverineFx 6.64.2 with the 6.38-built nupkg is green.
- **Test host:** upstream moved to xunit.v3 **4.0.2** on MTP 2.x (GH-4979), with a root `global.json` that sets
  `"test": { "runner": "Microsoft.Testing.Platform" }` and `UseMicrosoftTestingPlatformRunner=true` on test projects.
  It keeps `Microsoft.NET.Test.Sdk`, `xunit.runner.visualstudio` 4.0.1 and `GitHubActionsTestLogger` 2.4.1.
- **Leadership suite:** `LeadershipElectionCompliance` is now 23 `[BobcatSpec]` methods (was 19 `[Fact]`s). A subclass
  project references `Bobcat.Xunit` and `Bobcat.Generators` 1.0.0 and marks the class `[BobcatFeature("<name>")]`
  (upstream `RavenDbTests.LeaderElection`). `singular_agent_is_only_running_on_one` keeps its name.
- **Deduplication release (GH-4501):** core now always adds `ReleaseDeduplicationIdOnFailureFrame` in front of a
  transactional chain. It wraps the rest of the chain in `try/catch/finally` and calls `ReleaseAsync` once if the
  chain threw. `TransactionalFrame` (`Internals/TransactionalFrame.cs:116-123`) also releases in its rollback catch,
  so a failed attempt releases twice. The core frame sits outside `TransactionalFrame`, so its release runs after
  the rollback.
- **Atomic inbox claim:** `IMessageStore.TryClaimIncomingAsync(int ownerId, IReadOnlyList<Envelope> incoming)` is new.
  Its default calls `ReassignIncomingAsync` and returns every envelope. Its doc says custom stores must override it.
  `DestinationRecovery` and `ListenerInboxRecovery` call it. `ReassignIncomingAsync` (`Internals/MongoDbMessageStore.cs:218`)
  only claims `ownerId == AnyNode` rows, but returns `Task`, so the default reports rows it lost as won.
- **Handled check:** `IMessageInbox.IsHandledAsync(Envelope, CancellationToken)` is new. Its default is `ExistsAsync`.
- **New inherited facts** (fact names from the source. Task 1 confirms which ones fail):
  - `MessageStoreCompliance` (51 → 79): `is_handled_*`, `a_row_stored_as_handled_is_handled`,
    `a_scheduled_row_is_not_handled`, `a_dead_lettered_message_is_not_handled`,
