# Wolverine 6.38.0 Upgrade + Review Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move Wolverine.MongoDB from WolverineFx 6.21.0 to the latest stable release (6.38.0, source tag `V6.38.0` = `3d0e0433fa6c1fd4a7f18064ac021bacbf33d5fa`, published 2026-09-15) and close the remaining review findings, one focused PR each.

**Architecture:** Two PRs (retry retention, provider catch-all) target `main` directly because they need no new upstream API. The upgrade PR is the compatibility foundation (package pins, submodule, xUnit v3 harness, three `INodeAgentPersistence` contract changes). Every feature PR that needs a 6.38 API stacks on the upgrade branch and contains only its own diff. Docs (CHANGELOG / README / CLAUDE.md / FOLLOWUPS) are collected in one final docs PR to avoid the same hunk being edited in ten branches.

**Tech Stack:** .NET 9/10, MongoDB.Driver 3.11.x, WolverineFx 6.38.0 (`external/wolverine` submodule at `V6.38.0`), xUnit v3 3.2.2 (library tests), xUnit 2.9.3 (demo, unchanged), Shouldly, Testcontainers.MongoDb replica set.

## Global Constraints

- Latest stable Wolverine: **6.38.0** (NuGet `WolverineFx`, `WolverineFx.ComplianceTests`, `WolverineFx.RabbitMQ`, `WolverineFx.RuntimeCompilation` all publish 6.38.0). Source tag `V6.38.0`, commit `3d0e0433fa6c1fd4a7f18064ac021bacbf33d5fa`.
- Branch naming: `codex/<topic>`, one worktree per PR under `.claude/worktrees/`.
- Never disable NuGet auditing, never weaken `TreatWarningsAsErrors`. `Directory.Build.rsp` (NU1902 stopgap) is **deleted** in the upgrade PR because ≥ 6.36.0 removes the flagged `Microsoft.SourceLink.GitHub 8.0.0` pin.
- Every PR: build net9.0 + net10.0, run the touched tests against the Testcontainers replica set, run the full single-node suite; the upgrade PR also runs multinode on both TFMs and the demo against the packed nupkg.
- Do not merge. Do not touch the five merged fixes (PRs 221–225).
- Feature PRs do not edit CHANGELOG.md / README.md / CLAUDE.md / FOLLOWUPS.md — the docs PR does.
- After any Internals API change: `rm -rf src/Wolverine.MongoDB.Tests/Internal/Generated` before building locally.
- Run `Category=multinode` serially (one worktree at a time).

## Verified facts (2026-09-15, submodule at V6.38.0)

- Compile breaks vs 6.38.0 (library): exactly three, all `INodeAgentPersistence`: `Task<bool> MarkHealthCheckAsync`, `Task ReregisterNodeAsync(WolverineNode, CancellationToken)`, `Task<bool> TryClaimAssignmentAsync(Guid, Uri, CancellationToken)`.
- New defaulted members (no compile impact): `IMessageOutbox.StoreOutgoingAsync(IReadOnlyList<Envelope>, int)`, `IMessageStore.Deduplication`, `IMessageStore.RecurringMessages`, `IMessageStoreAdmin.AssertStorageProvisionedAsync`, `IMessageStoreAdmin.MigrateAsync(AutoCreate?)`, `IPersistenceFrameProvider.TryBuild{All,FirstOrDefault,Queryable}Frame`, `TryDetermineTransactionOwnerType`, chain-aware `DetermineSagaIdType`.
- `IsCatchAll` already exists in 6.21.0 (`IPersistenceFrameProvider.cs`); `OrderedPersistenceProviders` sorts `IsCatchAll ? 1 : 0` stably; `TryFindPersistenceFrameProvider` picks `candidates.First()`.
- `Wolverine.ComplianceTests` lives at `external/wolverine/src/Testing/Wolverine.ComplianceTests/`, references `xunit.v3.extensibility.core` 3.2.2, is published to NuGet as `WolverineFx.ComplianceTests` 6.38.0. Consumers: `<OutputType>Exe</OutputType>`, `xunit.v3`, `xunit.runner.visualstudio` 3.1.5, keep `Microsoft.NET.Test.Sdk`. `IAsyncLifetime` is `ValueTask`. `ITestOutputHelper` is in `Xunit`.
- Newly inherited compliance facts that will FAIL on the upgrade branch until their own PR merges: `MessageStoreCompliance.storing_outgoing_envelopes_marks_them_as_persisted_in_the_outbox` (PR 5), `DeadLetterAdminCompliance.query_by_replayable_flag` (PR 4). Report, do not skip.
- `RescheduleExistingEnvelopeForRetryAsync` in RDBMS never clears `keep_until`/restores body either, but RDBMS expiry is status-gated (`where status='Handled'`). MongoDB's `keepUntil` TTL index is NOT status-gated → a rescheduled retry with a stale `keepUntil` is deleted by the TTL monitor. That is the MongoDB-specific defect.
- Dedup: no upstream hook enlists the claim in the handler transaction; `RdbmsDeduplicationStore` claims on its own connection and core omits the release frame for transactional chains. MongoDB PR adds release-on-rollback inside `TransactionalFrame`'s catch so a rolled-back handler does not leave a claim that suppresses the retry.
- `RecurringMessageCompliance.the_opt_in_is_schema_neutral_for_hosts_without_schedules` casts the store to `Weasel.Core.Migrations.IDatabase` → cannot pass for a non-Weasel store; suite hosted via a RavenDb-style `Bridge` with forwarding facts; that fact replaced by a same-named MongoDB-native one (CI must be green).
- Durability maintenance settings consumed only by the RDBMS `DurabilityAgent`: `NodeRecordRetention` (10 000), `NodeRecordPruningPeriod` (1h), `NodeEventRecordExpirationTime` (5d), `OrphanedMessageSweepPollingTime` (5s), `OrphanedMessageReleaseBatchSize` (5000), `OrphanedMessageReleaseMaxBatchesPerCycle` (20), `DeduplicationCleanupPollingTime` (5m), `DeduplicationCleanupBatchSize` (5000). Cosmos/RavenDb implement none.
