# WolverineFx 6.22.0 Upgrade — Per-Task Session Prompts

One fresh Claude Code session per task, in the order below. Start each session **in the repository root** (not a stale worktree), set the session model first (`/model` — the recommended model is listed per task), then paste the prompt.

Conventions baked into every prompt (identical to `2026-07-07-review-findings-remediation-prompts.md`):
- The session verifies its **precondition** (prerequisite PRs merged to `main`) before doing anything.
- Execution goes through `superpowers:executing-plans` against the referenced plan task **only** — no scope creep.
- Branch + PR mechanics come from the plan's "Git & PR Workflow" section (worktree per task; `gh pr view --json statusCheckRollup` to verify checks, **not** the rtk `--watch` tail).
- **Do not invent Wolverine or MongoDB.Driver APIs.** The plan's "Verified API Facts" section is the source of truth; confirm each against the `external/wolverine` submodule with a one-line `git show`/grep rather than guessing. If an API differs from the plan, **stop and report** — do not improvise a substitute.
- If a plan assumption doesn't hold (an API missing, a test that can't fail as predicted), the session stops and reports instead of improvising. Two non-obvious verification failures → stop, report, re-run the task on Opus 5.
- Fix tasks are **red-first**: the test must reproduce the failure mode BEFORE the fix (run it, quote the failure), then pass after. A fix PR whose test never went red does not close its finding.
- Local build hygiene: after any Wolverine version change or `Internals` API change, delete the gitignored `src/Wolverine.MongoDB.Tests/Internal/Generated` directory before building — stale codegen breaks local builds in ways CI never reproduces.
- When finishing, update the plan doc in the same PR (tick step checkboxes + the status-table row).

**Precondition for everything below:** the version-unification PR (branch `chore/unify-package-versions`) is merged to `main`, so `main` has `WolverineFx` at range floor `6.21.0`, the `external/wolverine` submodule at `V6.21.0`, `MongoDB.Driver` at `[3.10.0,4.0.0)` / `3.10.0`, and no explicit `Microsoft.SourceLink.GitHub` `PackageReference`. Verify with `git submodule status` and by reading both `Directory.Packages.props` files.
